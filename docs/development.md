# Development

[Русская версия](ru/development.md)

Module: `github.com/tapclap/k8s-selectel-operator`. The layout is kubebuilder multigroup. One binary runs every controller. A later Selectel product is a new API group and controller. It should reuse `internal/selectel/iam` rather than copy token handling.

| Path | Contents |
| --- | --- |
| `api/selectel/v1alpha1` | `Project` types |
| `api/cdn.selectel/v1alpha1` | CDN `Resource` types |
| `api/openapi/cdn.yaml` | Selectel CDN OpenAPI spec |
| `internal/selectel/iam` | Keystone token client and in-process cache |
| `internal/selectel/access` | Namespace and certificate allowlist |
| `internal/selectel/cdn` | CDN client wrapper |
| `internal/selectel/cdn/cdnapi` | Client generated by oapi-codegen. Do not edit. |
| `internal/controller/selectel` | `Project` controller |
| `internal/controller/cdn.selectel` | CDN `Resource` controller |
| `config/` | CRDs, RBAC, manager, samples |
| `helm/selectel-operator` | Controller chart. Includes the same CRDs. |
| `helm/selectel-operator-crds` | CRDs only, for a separate install. |
| `.github/workflows/release.yml` | On a `v*` tag, publishes the image, both charts, and a GitHub release. |

CRD types are written by hand with the same JSON names as the CDN API. `controller-gen` cannot generate DeepCopy for the oapi-codegen models, so the custom resource and the generated client are separate Go types. The controller converts the spec with `encoding/json`.

Generated files, left in place and not edited by hand:

- `config/crd/bases/*.yaml`
- `config/rbac/role.yaml`
- `**/zz_generated.*.go`
- `internal/selectel/cdn/cdnapi/zz_generated.client.go`
- `PROJECT`

`// +kubebuilder:scaffold:*` comments are required by the kubebuilder CLI.

## Commands

```sh
make manifests   # CRDs, ClusterRole, and copies of the CRDs in both Helm charts
make generate    # DeepCopy and the CDN client
make test        # fmt, vet, httptest, envtest
make run         # manager against the current kubeconfig
make lint-fix    # golangci-lint --fix
```

`make test` does not call Selectel. IAM and CDN tests use `httptest`. Controller tests use envtest. End-to-end tests under `test/e2e` are excluded. They expect a dedicated [Kind](https://kind.sigs.k8s.io/) cluster, not a shared development cluster:

```sh
make test-e2e
```

After a live deploy, confirm on one project that a resource can be created, that `status.cdnDomain` appears, that an origin change is applied, and whether the Selectel name is free after `deletionPolicy: Deactivate`. The unit tests assert that deactivation sends `{"active": false}`. They cannot show whether Selectel then releases the name.

## CDN client

`make generate` runs oapi-codegen (`OAPI_CODEGEN_VERSION`, default v2.5.1) with `api/openapi/oapi-codegen.yaml`. The wrapper in `internal/selectel/cdn` sets `X-Auth-Token`, accepts 200/201/202, maps 401 and 404 to sentinel errors, and honors `Retry-After` on 429. List calls request both `active=true` and `active=false` because the API defaults to active resources only.

Regenerate the client after editing `api/openapi/cdn.yaml`, then run `make test`.

## Another Selectel product

Add an API group (`dns.selectel.tapclap.com` or similar) with `kubebuilder create api`, a controller under `internal/controller/<group>`, and wire it in `cmd/main.go`. Pass the same `iam.Cache` the Project and CDN controllers already share. Keep product URLs and resource logic in that group. Project, the credentials namespace, and the token cache stay common.
